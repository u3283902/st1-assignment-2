
# Reflection 
AI noticed a lot of inconsistencies within my system requirements that I did not consider, specifically by using undefined and broad terms. For example, it helped me realise that "patient details" in FR-01 did not specify which fields were required. Some other function requirements were also inconsistent, since FR-09 assumed features that FR-04 didn't specify.

Although AI helped me understand requirements, it also overreached. For User Story 4, AI assumed the system should have notification features for practitioners, even though the client never specified this as a requirement.

The biggest change I made after review was merging FR-07 and FR-08 into one functional requirement to better outline how "updating" and "cancelling/rescheduling" are really the same function under different names.

It's important to have evidence for requirements so we prevent building a system that doesn't meet the needs of the client. By classifying each suggestion as Accepted, Modified, Rejected, or Unverified, I better understood which requirements needed more consideration.
